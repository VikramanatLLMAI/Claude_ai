
  4. Create `lib/services/instruction-service.ts` -- service layer for saving instructions with token validation:
     - Import `estimateTokenCount`, `TOKEN_LIMITS`, `SERVER_MARGIN` from `@/lib/token-counter`
     - Import `auditLog, PrismaTransactionClient` from `@/lib/services/audit-service`
     - Import `prisma` from `@/lib/db`

     Note: Sanitization of prompt content happens at composition time in `lib/services/system-prompt-service.ts` (Plan 03), NOT at save time. The instruction service validates token budgets and stores plain text as-is.

     Functions:
     - `validateTokenBudget(text: string, limit: number): { valid: boolean; tokenCount: number; limit: number }` -- returns whether text is within limit (with SERVER_MARGIN)
     - `saveOrgInstructions(orgId, instructions, actorId, ipAddress)` -- validates token budget (700), updates OrgSettings.systemInstructions, audit logs (action: 'org.instructions.updated')
     - `saveRoleInstructions(roleId, orgId, instructions, actorId, ipAddress)` -- validates token budget (500), updates Role.systemInstructions, audit logs (action: 'role.instructions.updated')
     - Both save functions return `{ success: true }` or `{ success: false, error: string }`.
     - Server-side validation: reject if `estimateTokenCount(text) > Math.ceil(limit * SERVER_MARGIN)`.
     - Instructions are plain text only -- no HTML/markdown stored.

  5. Add Zod schemas to `lib/validation.ts`:
     - `OrgInstructionsSchema` -- z.object({ systemInstructions: z.string().max(TOKEN_LIMITS.org * 4 * SERVER_MARGIN) })
     - `RoleInstructionsSchema` -- z.object({ systemInstructions: z.string().max(TOKEN_LIMITS.role * 4 * SERVER_MARGIN) })
