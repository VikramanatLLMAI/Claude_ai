**1. Validation schemas (add to lib/validation.ts):**

```typescript
const CreateApiKeySchema = z.object({
  name: z.string().min(1).max(100),
  apiKey: z.string().min(10), // raw key, will be encrypted
  provider: z.string().default("anthropic"),
  organizationIds: z.array(z.string().uuid()).optional().default([]),
})

const UpdateApiKeyAssignmentsSchema = z.object({
  organizationIds: z.array(z.string().uuid()),
})
```

**2. Service layer (lib/services/api-key-service.ts):**

Functions (all use raw `prisma`, not tenantDb -- platform-level):

- `listApiKeys()`: Return all PlatformApiKey records with `assignments` relation (include organization name). Do NOT return encryptedKey in the response. Instead compute `maskedKey`: first 7 chars + "..." + last 4 chars of decrypted key. Include `_count.assignments` for number of assigned orgs.

- `createApiKey({ name, apiKey, provider, organizationIds })`: Encrypt the raw key using `encrypt()` from lib/encryption.ts. Create PlatformApiKey record. If organizationIds provided, create PlatformApiKeyAssignment records in a transaction with audit logging.

- `deleteApiKey(id)`: Delete PlatformApiKey (cascade deletes assignments). Audit log.

- `updateApiKeyAssignments(id, organizationIds)`: In a transaction, delete all existing PlatformApiKeyAssignment for this key, then create new ones for the provided org IDs. Audit log.

- `testApiKey(id)`: Decrypt the key, make a minimal Anthropic API call (create message with max_tokens=1, model claude-haiku-4-5-20251001, content "test"). Return `{ valid: true }` on success, `{ valid: false, error: string }` on 401/403/other. Update `lastTestedAt` on the PlatformApiKey record regardless of result.

- `getDecryptedKey(id)`: Internal helper, returns decrypted key string. NOT exported.

All mutations wrapped in `prisma.$transaction()` with `auditLog.record()` co-located.

**3. API routes:**

`GET /api/super-admin/api-keys/` (route.ts):
- requireSuperAdmin(req)
- Call listApiKeys()
- Return JSON array with masked keys + assignment info

`POST /api/super-admin/api-keys/` (route.ts):
- requireSuperAdmin(req)
- Validate body with CreateApiKeySchema
- Call createApiKey(validated data)
- Return 201 with created key (masked)

`GET /api/super-admin/api-keys/[id]` ([id]/route.ts):
- requireSuperAdmin(req)
- Return single key with assignments (masked)

`PATCH /api/super-admin/api-keys/[id]` ([id]/route.ts):
- requireSuperAdmin(req)
- Validate body with UpdateApiKeyAssignmentsSchema
- Call updateApiKeyAssignments(id, organizationIds)
- Return updated key

`DELETE /api/super-admin/api-keys/[id]` ([id]/route.ts):
- requireSuperAdmin(req)
- Call deleteApiKey(id)
- Return 204

`POST /api/super-admin/api-keys/[id]/test` ([id]/test/route.ts):
- requireSuperAdmin(req)
- Call testApiKey(id)
- Return `{ valid: boolean, error?: string, lastTestedAt: string }`

All routes follow the pattern: `requireSuperAdmin -> validate -> getIpAddress -> service fn -> error mapping`.
