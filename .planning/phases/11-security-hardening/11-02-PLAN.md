<task type="auto">
  <name>Task 2: Add rate limiting and origin validation to API routes</name>
  <files>app/api/chat/route.ts, app/api/conversations/route.ts, app/api/conversations/[id]/route.ts, app/api/conversations/[id]/messages/route.ts, app/api/artifacts/route.ts, app/api/messages/[id]/feedback/route.ts, app/api/mcp/connections/route.ts, app/api/user/preferences/route.ts, app/api/user/anthropic/route.ts</files>
  <action>
For authenticated API routes, add rate limiting keyed by user ID (from auth result) and origin validation on mutation methods.

**Chat route** (`app/api/chat/route.ts`) -- special chat tier:
After `requireOrgAuth(req)` succeeds (need the user ID for keying), add:
```typescript
const rl = checkRateLimit(`chat:${user.id}`, RATE_LIMITS.chat);
if (!rl.allowed) return rateLimitResponse(rl.retryAfterSeconds);
```
Also add origin validation since POST is a mutation.

**General API routes** -- standard api tier:
For each route's mutation handlers (POST, PUT, PATCH, DELETE), after auth check succeeds, add:
```typescript
const rl = checkRateLimit(`api:${user.id}`, RATE_LIMITS.api);
if (!rl.allowed) return rateLimitResponse(rl.retryAfterSeconds);
```
And origin validation:
```typescript
if (!validateOrigin(req)) return originDeniedResponse();
```

Apply to these routes (mutation handlers only -- GET handlers do NOT get origin validation but DO get rate limiting):
- `app/api/conversations/route.ts` -- POST (create) and GET (list)
- `app/api/conversations/[id]/route.ts` -- GET, PATCH, DELETE
- `app/api/conversations/[id]/messages/route.ts` -- POST
- `app/api/artifacts/route.ts` -- POST
- `app/api/messages/[id]/feedback/route.ts` -- POST
- `app/api/mcp/connections/route.ts` -- POST, GET
- `app/api/user/preferences/route.ts` -- PUT
- `app/api/user/anthropic/route.ts` -- POST, DELETE

For GET handlers: add rate limiting with `api` tier but skip origin validation (GET is safe).
For POST/PUT/PATCH/DELETE handlers: add both rate limiting and origin validation.

Note: Super Admin routes and Org Admin routes also need rate limiting and origin validation, but there are many of them. Apply the same pattern to ALL mutation handlers under:
- `app/api/super-admin/` (all POST/PUT/PATCH/DELETE handlers)
- `app/api/org/[slug]/admin/` (all POST/PUT/PATCH/DELETE handlers)

For super admin routes, key rate limit by user ID from `requireSuperAdmin()` result.
For org admin routes, key by user ID from `requireOrgAuth()` or `requireOrgAdmin()` result.

Use a systematic approach: find all route.ts files with POST/PUT/PATCH/DELETE exports, add rate limiting + origin validation to each.
