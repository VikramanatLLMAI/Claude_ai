**Step 2: Create lib/services/invitation-service.ts**

Import: `prisma` from `@/lib/db`, `auditLog` from `./audit-service`, `generateToken` from `@/lib/encryption`, `resend` from `@/lib/email/resend`, `InvitationEmail` from `@/lib/email/templates/invitation-email`.

Constants:
```typescript
const INVITATION_EXPIRY_DAYS = 7;
const FROM_EMAIL = process.env.RESEND_FROM_EMAIL || 'LLMatscale.ai <onboarding@resend.dev>';
const ROOT_DOMAIN = process.env.ROOT_DOMAIN || 'llmatscale.ai';
```

Functions:

1. **`sendInvitationEmail(params)`** — Internal helper
   - Accepts: `{ recipientEmail, orgName, orgSlug, inviterName, roleName, token }`
   - Build acceptUrl:
     - Dev: `http://localhost:3000/org/${orgSlug}/register?token=${token}`
     - Prod: `https://${orgSlug}.${ROOT_DOMAIN}/register?token=${token}`
   - If `process.env.RESEND_API_KEY` is not set: log invitation details to console (`console.log('[DEV] Invitation email would be sent to:', recipientEmail, 'Accept URL:', acceptUrl)`) and return early. This allows development without a Resend account.
   - Otherwise: call `resend.emails.send()` with the React Email template
   - Handle errors: log and throw `Failed to send invitation email`
   - Return email data from Resend

2. **`createInvitation(data, orgContext, actorId, ipAddress)`** — OUSR-01
   - `data`: `{ email, roleId }`
   - `orgContext`: organization from auth context (id, name, slug)
   - Validate the roleId belongs to this org: `prisma.role.findFirst({ where: { id: roleId, organizationId: orgContext.id } })`
   - If role not found → throw "Role not found in this organization"
   - Check if email already has a PENDING invitation for this org: `prisma.invitation.findFirst({ where: { email, organizationId: orgContext.id, status: 'PENDING' } })`
   - If existing pending invitation → throw "An invitation is already pending for this email"
   - NOTE: Per CONTEXT.md, do NOT check if email is already registered at invite-send time. Multiple orgs CAN invite the same email. The uniqueness check happens at registration/acceptance time.
   - Use `prisma.$transaction()`:
     a. Create Invitation: `{ organizationId, email, roleId, invitedById: actorId, token: generateToken(), status: 'PENDING', expiresAt: new Date(Date.now() + INVITATION_EXPIRY_DAYS * 24 * 60 * 60 * 1000) }`
     b. Audit log: `action: 'invitation.created'`, targetType: 'Invitation', metadata: `{ email, roleName: role.name }`
   - After transaction: Send invitation email (outside transaction since email is non-transactional)
   - Get inviter name from `prisma.user.findUnique({ where: { id: actorId }, select: { name: true } })`
   - Call `sendInvitationEmail()` with all params
   - Return invitation record

3. **`revokeInvitation(invitationId, orgId, actorId, ipAddress)`** — OUSR-09, SAFE-02
   - Find invitation by id, verify it belongs to this org and status is PENDING
   - If not found or wrong org → throw "Invitation not found"
   - If not PENDING → throw "Only pending invitations can be revoked"
   - **SAFE-02 guard: If this invitation is for an admin role** (role has `org_admin` permission or role name is "Org Admin"), count remaining admin coverage before revoking:
     a. Count active OrgMembers with admin role in this org: `prisma.orgMember.count({ where: { organizationId: orgId, status: 'ACTIVE', role: { OR: [{ permissions: { path: '$', array_contains: 'org_admin' } }, { name: 'Org Admin' }] } } })`
     b. Count remaining PENDING invitations for admin roles in this org (excluding the one being revoked): `prisma.invitation.count({ where: { organizationId: orgId, status: 'PENDING', id: { not: invitationId }, role: { OR: [{ permissions: { path: '$', array_contains: 'org_admin' } }, { name: 'Org Admin' }] } } })`
     c. If (activeAdminMembers + remainingPendingAdminInvitations) === 0 → throw "Cannot revoke: this would leave the organization with no admin. At least one active admin or pending admin invitation must exist."
     d. NOTE: Use Prisma JSON filtering for the permissions array. If Prisma JSON filtering is complex, simplify by loading the role and checking permissions in code: `const role = invitation.role; const isAdminRole = role.name === 'Org Admin' || (Array.isArray(role.permissions) && role.permissions.includes('org_admin'));`
   - Use `prisma.$transaction()`:
     a. Update invitation status to 'REVOKED'
     b. Audit log: `action: 'invitation.revoked'`
   - Return updated invitation

4. **`resendInvitation(invitationId, orgId, actorId, ipAddress)`** — OUSR-09
   - Find invitation by id, verify it belongs to this org
   - If not found or wrong org → throw "Invitation not found"
   - Status must be PENDING or EXPIRED (can resend expired invitations per CONTEXT.md)
   - If ACCEPTED or REVOKED → throw "Cannot resend accepted or revoked invitations"
   - Use `prisma.$transaction()`:
     a. Generate new token
     b. Update invitation: new token, status reset to 'PENDING', expiresAt reset to 7 days from now
     c. Audit log: `action: 'invitation.resent'`
   - After transaction: Re-send email with new token
   - Return updated invitation

5. **`listInvitations(orgId)`**
   - Fetch all invitations for this org
   - Include: role name, invitedBy user name
   - Lazy expiry check: for each PENDING invitation where `expiresAt < now()`, update status to 'EXPIRED' (batch update)
   - Order by: status (PENDING first), then createdAt desc
   - Return invitation list

**Step 3: Create Org Admin API routes for invitations**

**RESOLVED — requireOrgAdmin routing:**
Use `requireOrgAdmin(req)` from `lib/auth-middleware.ts` exactly as existing org-scoped routes (`/api/chat`, `/api/conversations`) do. In production, `resolveOrgSlug(req)` extracts the org slug from the subdomain host header (e.g., `acme.llmatscale.ai`). In development, the same resolution gap that affects ALL existing org-scoped API routes also affects these routes -- this is an existing Phase 1 gap (the chat page at `/org/[slug]/chat` calls `/api/chat` without a slug in the path). It is NOT specific to invitations and will be resolved holistically when the admin dashboard UI is built (Phases 5-6). For Phase 2, follow the identical pattern used by existing routes. Do NOT create alternative auth patterns.

`app/api/org/invitations/route.ts`:
- **GET**: Call `requireOrgAdmin(req)`, then `listInvitations(auth.organization.id)`. Return array.
- **POST**: Call `requireOrgAdmin(req)`, validate body with `CreateInvitationSchema`, call `createInvitation()`. Catch "already pending" → 409, "Role not found" → 400. Return 201.

`app/api/org/invitations/[id]/revoke/route.ts`:
- **POST**: Call `requireOrgAdmin(req)`, extract invitation `id` from params, call `revokeInvitation()`. Return 200.

`app/api/org/invitations/[id]/resend/route.ts`:
- **POST**: Call `requireOrgAdmin(req)`, extract invitation `id` from params, call `resendInvitation()`. Return 200.

**Step 4: Create default role API route**

`app/api/org/settings/default-role/route.ts`:
- **GET**: Call `requireOrgAdmin(req)`, fetch OrgSettings for this org, return `{ defaultRoleId }`.
- **PATCH**: Call `requireOrgAdmin(req)`, validate body with `SetDefaultRoleSchema`.
  - If `roleId` is not null: verify the role exists in this org and is not deleted
  - Update OrgSettings.defaultRoleId
  - NOTE: Cascade handling when a default role is deleted (ODEF-02) is deferred to Phase 4 (role deletion). Phase 2 only sets the field.
  - Audit log: `action: 'org.default_role_updated'`
  - Return updated settings.
