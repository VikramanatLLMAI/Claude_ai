**Org login page redesign** (app/org/[slug]/login/page.tsx):

Redesign the existing org login page with production-grade UI:

1. **Layout:** Centered card design using shadcn Card component. Two-column on desktop (branding left, form right), single column on mobile.

2. **Branding column (left):**
   - Org logo (from Organization.logoBase64) displayed prominently
   - If logoDisplayMode = PLATFORM_AND_ORG: show both org logo and "LLMatscale.ai" text
   - If logoDisplayMode = ORG_ONLY: show only org logo
   - Tagline below logo (from OrgSettings.loginTagline)
   - Welcome message below tagline (from OrgSettings.loginWelcomeMessage)
   - If no tagline/welcome message: show org name as fallback

3. **Form column (right):**
   - Keep existing login form logic (email/password, validation, session)
   - Upgrade to shadcn Input, Button, Label components
   - Add proper error states and loading states
   - "Forgot password?" link if applicable

4. **Theme application:** This is a server component. Fetch the org's active theme and apply `data-theme` attribute on the page wrapper. This ensures the login page uses the org theme before the user even logs in.

5. **Dark/light:** Respect system preference or apply default light mode for unauthenticated users.

**Onboarding wizard** (components/onboarding-wizard.tsx):

Multi-step wizard shown on first login to an org. Blocks access to chat until accepted.

1. **Step 1 - Welcome:**
   - Platform name + org name
   - "Welcome to [OrgName] on LLMatscale.ai"
   - Brief platform description
   - "Next" button

2. **Step 2 - Org Terms:**
   - Org-specific text from OrgSettings.onboardingText
   - If no org text configured: show generic "Your organization uses LLMatscale.ai for AI-powered chat. Please review and accept to continue."
   - If conversation visibility is enabled for the org: include notice "Your conversations may be reviewed by your organization administrator for compliance purposes."
   - Scrollable text area for long terms
   - "Next" button

3. **Step 3 - Confirmation:**
   - Summary of what user is agreeing to
   - Checkbox: "I have read and agree to the above terms"
   - "I Agree" button (disabled until checkbox checked)
   - On accept: POST /api/org/{slug}/onboarding → redirect to chat

4. **Step transitions:** Use Framer Motion for smooth slide transitions between steps. Progress indicator (dots or step numbers) at top.

**Chat page integration** (app/org/[slug]/chat/page.tsx):

Add onboarding check:
1. On mount, call `GET /api/org/{slug}/onboarding` to check if onboarding is required.
2. If required: render OnboardingWizard instead of the chat UI. Block chat access.
3. If already accepted (or no onboarding configured): render chat normally.
4. After wizard completion: reload chat page or set state to show chat.

This is a MINIMAL integration - just a conditional render check at the top of the chat page.
