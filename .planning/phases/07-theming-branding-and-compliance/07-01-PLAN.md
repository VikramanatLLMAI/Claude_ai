**Super Admin theme assignment API** (app/api/super-admin/organizations/[id]/themes/route.ts):

- GET: Return assigned themes + active theme for org. Uses requireSuperAdmin.
- PUT: Body `{ assignedThemes: string[], defaultTheme: string | null }`. Validates theme names. Calls `themeService.setOrgThemes()`. Returns 200.
- Follow existing API route pattern: requireSuperAdmin -> Zod validate -> getIpAddress -> service fn -> error mapping

**Org Admin theme selection API** (app/api/org/[slug]/admin/themes/route.ts):

- GET: Return assigned themes + current active theme for org. Uses requireOrgAdmin.
- PUT: Body `{ activeTheme: string }`. Calls `themeService.setActiveTheme()`. Server-side validates theme is in assigned set (OTHM-07). Returns 200 or 400 if theme not assigned.

**User-facing theme fetch** (app/api/org/[slug]/theme/route.ts):

- GET: Return `{ activeTheme: string | null }` for the org. Uses requireOrgAuth (any org member, not just admin). This is the endpoint the frontend calls on page load to apply the org theme.

**Cron cleanup route** (app/api/cron/cleanup/route.ts):
