**Fix 3: /api/auth/me org context resolution (Gap 2 backend)**

In `app/api/auth/me/route.ts`, the `resolveOrgSlug(req)` call returns null for `/api/auth/me` because the URL doesn't contain `/org/:slug/`. Fix by falling back to the session's `organizationId` when slug resolution fails.

The `requireAuth()` middleware already looks up the session. The session has an `organizationId` field. Modify the org context enrichment logic:

1. After `resolveOrgSlug(req)` returns null, also check if the session has an `organizationId`.
2. The auth object from `requireAuth()` only returns `{ user }`. We need to get the session's organizationId. Look at how `requireAuth` works -- it validates the session token. The session record has `organizationId`.

Approach: Modify the `/api/auth/me` handler to also look up the user's orgMember by querying with just `userId` when no slug is available but the user is not a super admin. Since the platform enforces one-user-one-org, we can find their single org membership directly:

```typescript
if (!user.isSuperAdmin) {
  let orgMember = null;
  const slug = resolveOrgSlug(req);

  if (slug) {
    orgMember = await prisma.orgMember.findFirst({
      where: {
        userId: user.id,
        organization: { slug, deletedAt: null, status: 'ACTIVE' },
      },
      include: { organization: true, role: true },
    });
  } else {
    // Fallback: find user's org membership directly (one user = one org)
    orgMember = await prisma.orgMember.findFirst({
      where: {
        userId: user.id,
        organization: { deletedAt: null, status: 'ACTIVE' },
      },
      include: { organization: true, role: true },
    });
  }

  if (orgMember) {
    response.organization = { ... };
    response.role = { ... };
  }
}
```

This preserves slug-based lookup when available (production subdomain routing) and falls back to direct membership lookup when slug is not in the URL path (dev mode calling `/api/auth/me`).

**Fix 1: Edit dialog pre-population (Gap 3)**

In `components/mcp/mcp-add-dialog.tsx`, the `useState` initializers only run on first mount. When `editData` changes (user clicks "Edit" on a different connection), the form state is stale.

Add a `useEffect` that syncs form state when `editData` changes or when the dialog opens:

```typescript
import { useState, useEffect } from "react"

// ... existing useState declarations remain ...

// Sync form state when editData changes (dialog opens for edit)
useEffect(() => {
  if (editData) {
    setName(editData.name)
    setServerUrl(editData.serverUrl)
    setAuthType(editData.authType)
    // Show advanced section if auth type is not 'none'
    if (editData.authType !== 'none') {
      setShowAdvanced(true)
    }
  } else {
    // Reset to empty when not editing (creating new)
    setName("")
    setServerUrl("")
    setAuthType("none")
    setShowAdvanced(false)
  }
  // Clear credential fields and errors on any editData change
  setOauthClientId("")
  setOauthClientSecret("")
  setApiKey("")
  setErrors({})
}, [editData])
```

Also update the `handleOpenChange` function to NOT reset fields on close (the useEffect handles it), just clear editData via the parent's callback.

**Fix 2: Error toast when personal MCP creation fails with 403 (Gap 2 frontend)**

In `components/settings-modal.tsx`, the `handleAddConnection` function (around line 742-761) throws an Error when the POST fails, but the `McpAddDialog` catches it with only `console.error`. The user sees no feedback.

Fix in `handleAddConnection`: instead of throwing, show a toast:

```typescript
const handleAddConnection = async (data: { ... }) => {
  const res = await fetch("/api/mcp/connections", {
    method: "POST",
    headers: getAuthHeaders(),
    body: JSON.stringify(data),
  })
  if (res.ok) {
    await fetchConnections()
  } else {
    const errorData = await res.json()
    if (res.status === 403) {
      toast.error("Personal MCP connections are not enabled for your role. Contact your admin.")
    } else {
      toast.error(errorData.error || "Failed to add connection")
    }
    throw new Error(errorData.error || "Failed to add connection")
  }
}
```
