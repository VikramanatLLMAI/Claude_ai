**Fix 1: ChartContainer sizing in `components/ui/chart.tsx`**

The root cause is that the ChartContainer div uses `flex justify-center` with `ResponsiveContainer width="100%" height="100%"`, but the div has no intrinsic height. When consumers pass `className="min-h-[300px] w-full"`, the flex container does not properly propagate this to the ResponsiveContainer child.

In the ChartContainer component's className list (around line 110), make these changes:
1. Replace `"flex justify-center text-xs [&_.recharts-responsive-container]:!h-full"` with `"flex flex-col text-xs"` — changing from `justify-center` to `flex-col` so the ResponsiveContainer stretches vertically to fill the min-height, and removing the `[&_.recharts-responsive-container]:!h-full` override since it is no longer needed.
2. Add `"min-h-[200px] w-full"` as a default minimum height in the className list so ChartContainer always has measurable dimensions even if consumers forget to pass min-h. Consumers can override with their own min-h classes (e.g., `min-h-[300px]`).
3. Add `"[&_.recharts-responsive-container]:flex-1"` to ensure the ResponsiveContainer grows to fill available space within the flex column.

The final className list should include these base classes:
```
"flex flex-col text-xs",
"min-h-[200px] w-full",
"[&_.recharts-responsive-container]:flex-1",
```
Plus all the existing Recharts styling override classes (the `[&_.recharts-*]` selectors for cartesian-axis, grid, cursor, dot, layer, polar-grid, radial-bar, rectangle, reference-line, sector, surface, tooltip-wrapper).

Keep `ResponsiveContainer width="100%" height="100%"` props unchanged — the flex-1 on its wrapper will give it proper dimensions now.

**Fix 2: Heatmap tooltip consistency in `components/admin/analytics-charts.tsx`**

On line 462, change the double dash `--` to a single dash `-` in the heatmap tooltip:

// Before:

This matches the Org Admin heatmap format on org-analytics-charts.tsx line 776.
