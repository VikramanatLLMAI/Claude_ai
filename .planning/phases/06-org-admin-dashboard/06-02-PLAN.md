<task type="auto">
  <name>Task 1: Org analytics service layer</name>
  <files>lib/services/org-analytics-service.ts</files>
  <action>
Create `lib/services/org-analytics-service.ts` following the platform-analytics-service.ts pattern. Use raw `prisma` with explicit `organizationId` filters (not tenantDb) for queries that join non-org-scoped tables (User, Session, PlatformApiKey). Use tenantDb or raw prisma with orgId filter for org-scoped models (UsageRecord, Conversation, Message, OrgMember, Invitation).

Define typed interfaces for each return type (export all for frontend use).

**getKpiSummary(orgId: string)** — OANA-01, OANA-02, OANA-14
- Active OrgMember count (status=ACTIVE)
- Suspended OrgMember count (status=SUSPENDED)
- Pending Invitation count (status=PENDING)
- Total Conversation count (organizationId=orgId)
- Total Message count (via conversations in org)
- Total tokens: SUM of inputTokens+outputTokens from UsageRecord (organizationId=orgId)
- Users near limits: count of active users where daily usage >= 80% of their role's limit (query UsageRecord for today, join Role for limits)

**getUsageTrends(orgId, startDate, endDate)** — OANA-07
- Daily token usage grouped by DATE(createdAt), split into inputTokens, outputTokens, thinkingTokens
- Raw SQL with `WHERE "organizationId" = $1 AND "createdAt" BETWEEN $2 AND $3 GROUP BY DATE("createdAt")`
- Return array of { date, inputTokens, outputTokens, thinkingTokens }

**getTokensByUserRoleModel(orgId, startDate, endDate)** — OANA-03
- Token usage grouped by userId+roleId+modelId
- Join OrgMember for user name, Role for role name
- Return array of { userName, roleName, modelId, inputTokens, outputTokens }

**getModelDistribution(orgId, startDate, endDate)** — OANA-04
- UsageRecord grouped by modelId, SUM tokens, COUNT requests
- Return array of { modelId, totalTokens, requestCount }

**getTopUsers(orgId, startDate, endDate, limit=10)** — OANA-05
- Top N users by total tokens (input+output)
- Join OrgMember+User for name, Role for role name
- Also include message count per user
- Return array of { userId, userName, roleName, totalTokens, messageCount }

**getPerRoleUsage(orgId, startDate, endDate)** — OANA-06
- UsageRecord grouped by roleId (via OrgMember join)
- Return array of { roleId, roleName, totalTokens, requestCount, userCount }

**getMcpUsage(orgId, startDate, endDate)** — OANA-08
- Count messages with role='tool' in org-scoped conversations grouped by DATE
- Return array of { date, toolCallCount }
- Note: if no MCP usage data exists, return empty array (acceptable per Phase 5 pattern)

**getAvgResponseTime(orgId, startDate, endDate)** — OANA-09
- AVG of requestDurationMs from UsageRecord grouped by modelId
- Return array of { modelId, avgDurationMs }
- If requestDurationMs field doesn't exist in UsageRecord, derive from Message createdAt differences or return empty (document in code)

**getErrorRate(orgId, startDate, endDate)** — OANA-10
- Messages with metadata containing errorType, grouped by error type
- Pattern from platform-analytics-service.ts getErrorRates
- Return array of { errorType, count }

**getPeakUsageHours(orgId, startDate, endDate)** — OANA-11
- EXTRACT(HOUR) and EXTRACT(DOW) from UsageRecord.createdAt
- Return array of { hour, dayOfWeek, count } for heatmap

**getInvitationStats(orgId)** — OANA-12
- Count Invitations grouped by status (PENDING, ACCEPTED, EXPIRED, REVOKED)
- Return array of { status, count }

**getApiKeyUsage(orgId, startDate, endDate)** — OANA-13
- Query PlatformApiKeyAssignment for keys assigned to this org
- For each key, show total usage (or aggregate if multiple keys)
- Return array of { keyName, maskedKey, totalTokens, requestCount }
- If attribution not possible, return org-level aggregate with note

**getUsersNearLimits(orgId)** — OANA-14
- Active OrgMembers with today's usage >= 80% of role daily limits
- Return array of { userId, userName, roleName, usagePercent, limitType ('requests'|'tokens') }

**getInactiveUsers(orgId)** — OANA-15
- OrgMembers where status=ACTIVE AND (lastActiveAt < 30 days ago OR lastActiveAt is null AND joinedAt < 30 days ago)
- Return array of { userId, userName, email, roleName, lastActiveAt, daysSinceActive }

<task type="auto">
  <name>Task 2: Org analytics API endpoint with section-based loading</name>
  <files>app/api/org/[slug]/admin/analytics/route.ts</files>
  <action>
Create `app/api/org/[slug]/admin/analytics/route.ts` following the super-admin analytics API pattern:

GET endpoint:
- Auth: `requireOrgAdmin(req)` — extract orgId from auth context
- Query params: `section` (required), `startDate`, `endDate`
- Default date range: last 30 days if not provided
- Section dispatch (switch statement):
  - `kpi` → getKpiSummary(orgId)
  - `trends` → getUsageTrends(orgId, startDate, endDate)
  - `users` → getTopUsers(orgId, startDate, endDate) + getUsersNearLimits(orgId) + getInactiveUsers(orgId)
  - `models` → getModelDistribution(orgId, startDate, endDate) + getAvgResponseTime(orgId, startDate, endDate)
  - `roles` → getPerRoleUsage(orgId, startDate, endDate)
  - `usage` → getTokensByUserRoleModel(orgId, startDate, endDate)
  - `mcp` → getMcpUsage(orgId, startDate, endDate)
  - `errors` → getErrorRate(orgId, startDate, endDate)
  - `peak` → getPeakUsageHours(orgId, startDate, endDate)
  - `invitations` → getInvitationStats(orgId)
  - `apiKeys` → getApiKeyUsage(orgId, startDate, endDate)
  - `all` → call all sections and combine into single response object
  - default → return 400 "Invalid section"

Also support `?export=csv&section=X` for per-section CSV export (CONTEXT.md decision):
- When export=csv, format the section data as CSV string with headers
- Use the escapeCsvValue pattern from audit-log-service.ts
- Return as text/csv with Content-Disposition header
- File naming: `org-analytics-{section}-{date}.csv`
