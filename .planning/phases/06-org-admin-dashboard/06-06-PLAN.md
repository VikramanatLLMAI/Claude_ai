**API Routes:**

Create `app/api/org/[slug]/admin/audit-logs/route.ts`:
- GET: requireOrgAdmin → extract orgId from auth context
- If ?meta=true: call getAvailableActions() and getAuditLogUsers() but filter users to only those in this org. Return { actions, users }.
- Otherwise: Parse query params with AuditLogFilterSchema, FORCE organizationId to auth.organization.id (never trust client input for org scoping)
- Call listAuditLogs(filters) → return JSON response
- This is essentially a thin wrapper around the existing audit-log-service with enforced org scoping

Create `app/api/org/[slug]/admin/audit-logs/export/route.ts`:
- GET: requireOrgAdmin → extract orgId
- Parse format (csv|json), date range, action, user filters from query params
- FORCE organizationId = auth.organization.id
- Call exportAuditLogs(filters, format) → return file response with Content-Disposition
- Same UTF-8 BOM and 10,000 row cap as Super Admin export

**Page:**

Create `app/org/[slug]/admin/audit-logs/page.tsx`:
- Mirror `app/super-admin/audit-logs/page.tsx` EXACTLY (per CONTEXT.md "Mirror Super Admin pattern exactly")
- Key differences from Super Admin version:
  1. Uses requireOrgAdmin auth (via API calls to /api/org/{slug}/admin/audit-logs)

- Pagination controls at bottom (page size selector: 10/25/50, page navigation)
- Export buttons: CSV and JSON (using fetch+blob+anchor pattern with auth headers)
- Loading skeleton during data fetch
- Empty state when no audit logs match filters

**API Routes:**

Create `app/api/org/[slug]/admin/settings/api-keys/route.ts`:
- GET: requireOrgAdmin → extract orgId
- Query PlatformApiKeyAssignment where organizationId=orgId, include PlatformApiKey (select: id, name, maskedKey, provider, createdAt, lastTestedAt)
- Return JSON array of assigned keys with masked values
- This is READ-ONLY — no POST/PATCH/DELETE (Org Admin cannot modify keys)

Create `app/api/org/[slug]/admin/settings/api-keys/[id]/test/route.ts`:
- POST: requireOrgAdmin → extract orgId
- Verify the key assignment exists for this org (security check — can't test keys from other orgs)
- Decrypt the key (using existing encryption utils)
- Test validity by making a lightweight Anthropic API call (same pattern as Super Admin key test)
- Return { valid: boolean, error?: string }
- Record audit log: 'api_key.tested'
