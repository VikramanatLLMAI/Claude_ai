<objective>
Password policy management, force password reset, and forced password change flow.

Purpose: Give Org Admins control over password security via configurable policies and force-reset capabilities, while enforcing password changes through a dedicated forced change page that intercepts login when needed. This delivers enterprise-grade password security without immediate lockout on policy changes.

Output: Security page in admin console, password policy CRUD API, force reset APIs (individual + bulk), forced password change page, login route integration for redirect, auth middleware guard.
</objective>

  **Part A: Login route integration**

  Modify `app/api/auth/login/route.ts`:
  After successful password verification and session creation, add:

  ```typescript
  import { checkPasswordChangeRequired } from '@/lib/services/password-policy-service';
  import { getPasswordPolicy } from '@/lib/services/password-policy-service';

  // After successful auth, check if password change is required
  if (orgMember) {
    const policy = await getPasswordPolicy(orgMember.organizationId);
    const changeRequired = await checkPasswordChangeRequired(user, orgMember, policy);
    if (changeRequired?.required) {
      // Still create session (user needs it to access the change page)
      // But flag the response
      return Response.json({
        user: { id: user.id, email: user.email, name: user.name },
        token,
        expiresAt: expiresAt.toISOString(),
        forcePasswordChange: true,
        reason: changeRequired.reason, // 'expired' | 'admin_forced'
      });
    }
  }
  ```

  The frontend login handler must check for `forcePasswordChange: true` and redirect to `/org/[slug]/force-password-change` instead of the chat page.

  OPWD-05: Existing passwords that violate new policy are caught here. When the user logs in, `checkPasswordChangeRequired` evaluates the force flag and expiry. If neither triggers, the login succeeds normally -- no lockout.

  **Part B: Auth middleware guard**

  In `lib/auth-middleware.ts`, inside `requireOrgAuth()`, add a check:
  After loading the orgMember, if `orgMember.forcePasswordChange === true`:
  - Check if the current request URL is the force-password-change page or the change-password API
  - If NOT, return a 403 with `{ error: 'Password change required', code: 'FORCE_PASSWORD_CHANGE', redirectTo: '/org/{slug}/force-password-change' }`
  - This is the server-side enforcement -- even if the user bypasses the frontend redirect, the API will block them

  Exempt paths: `/api/auth/change-password`, `/api/auth/logout`, `/org/[slug]/force-password-change`

    - Current password input (required)
    - New password input (required, with live validation against org policy)
    - Confirm new password input (must match)
    - Password requirements checklist (dynamically shows org policy requirements with check/x icons)
    - Submit button: "Change Password"
  - On submit: POST /api/auth/change-password with { currentPassword, newPassword }
