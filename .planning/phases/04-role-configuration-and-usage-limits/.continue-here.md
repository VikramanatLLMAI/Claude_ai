<bugs_to_fix>

### BUG-1 [BLOCKER] Session type not enforced on /admin/* routes
- Symptom: Org user (Alice) navigating to /admin/login is auto-redirected into /admin/models shell
- Root cause: `app/admin/layout.tsx` `hasValidSession()` only checks token expiry — does NOT check
  `isSuperAdmin`. Any valid session (org user or super admin) passes the guard.
- Fix: Read session from localStorage, parse the session JSON, check `isSuperAdmin === true`.
  If false, redirect to /org/[slug]/chat (read slug from session).
- Key file: `app/admin/layout.tsx`

### BUG-2 [BLOCKER] Super Admin session breaks org chat (session type bleed)
- Symptom: Super Admin visiting /org/acme-corp/login is auto-redirected into /org/acme-corp/chat
  using Super Admin session → 9 API 403 errors, model selector stuck forever
- Root cause: `components/org-login-page.tsx` (client component) detects any active session and
  redirects to chat — does NOT check that the session belongs to an org member (not a super admin)
- Fix: In the session-redirect logic in OrgLoginPage, check `session.isSuperAdmin`. If true,
  do NOT redirect — show the login form so the super admin can log in as an org user.
- Key file: `components/org-login-page.tsx`

### BUG-3 [BLOCKER] All /admin/* routes except /admin/models return 404
- Symptom: /admin/organizations, /admin/super-admins, /admin/api-keys etc. all show
  "Organization not found" page
- Root cause: These pages simply don't exist yet as Next.js page files in `app/admin/`.
  The existing `app/org/[slug]/` dynamic route is NOT the cause — Next.js serves static
  segments before dynamic ones. The 404 is because `app/admin/organizations/page.tsx`,
  `app/admin/super-admins/page.tsx` etc. don't exist.
  Phase 5 was supposed to build the Super Admin Dashboard. The sidebar shows 6 "Soon" items
  because those pages haven't been built yet.
- Note: This is NOT a routing conflict bug — it's just unbuilt pages. Phase 5 builds them.
- REVISED SEVERITY: This is expected Phase 5 work, NOT a blocker bug. Remove from fix list.

### BUG-4 [MAJOR] Root URL / with active org session redirects to flat /chat
- Symptom: Logged-in org user visits localhost:3000, lands on /chat (not /org/acme-corp/chat)
- Root cause: `components/find-my-org.tsx` client component detects active session and redirects,
  but constructs the wrong URL — uses `/chat` instead of `/org/${session.orgSlug}/chat`
- Fix: Read `session.orgSlug` (or `session.organizationSlug`) from localStorage session JSON
  and redirect to `/org/${slug}/chat`. For super admins, redirect to `/admin`.
- Key file: `components/find-my-org.tsx`

### BUG-5 [MAJOR] Deprecate Model has no confirmation dialog
- Symptom: Clicking orange circle-slash on /admin/models immediately deprecates the model
- Root cause: `app/admin/models/page.tsx` deprecate handler calls API directly without a
  confirmation step
- Fix: Add AlertDialog confirmation (same pattern as existing Delete confirmation in that file)
- Key file: `app/admin/models/page.tsx`
</bugs_to_fix>
