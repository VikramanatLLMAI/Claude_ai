  <action>
Read the full settings-modal.tsx (67KB). Then apply consistent visual polish across all 8 tabs (Profile, General, Appearance, API Keys, MCP, Instructions, Sessions, Advanced).

**Per user decision:** Keep as modal. Keep existing 8-tab structure with no consolidation. Improve spacing, typography, form controls, and visual hierarchy.

**Global modal changes:**
1. **Modal sizing:** Ensure the DialogContent has proper responsive sizing. Use `max-w-2xl` (or `max-w-[640px]`). Set `max-h-[85vh]` on the modal to prevent viewport overflow.
2. **Tab content scrolling:** Each TabsContent should have `overflow-y-auto` with a max-height that accounts for the tab bar and modal header. This prevents content from being cut off in tabs with lots of content (like MCP or Sessions).
3. **Tab bar styling:** Ensure the TabsList is visually clean -- consistent font size, proper spacing, no visual artifacts. Tabs should wrap or scroll horizontally if needed on smaller screens.

**Per-tab polish pattern:**
For each tab, apply these consistent patterns:

1. **Section headings:** Use `<h3 className="text-sm font-medium text-foreground">Section Title</h3>` for section headers within tabs.
2. **Section spacing:** Use `space-y-6` between major sections, `space-y-4` within sections, separated by `<Separator />` (from `@/components/ui/separator`) between major sections.
3. **Form labels:** Use `<Label>` component with `text-sm font-medium` for all form labels. Every input should have a label.
4. **Helper text:** Use `<p className="text-xs text-muted-foreground mt-1">` for helper/description text below inputs.
5. **Input sizing:** All text inputs should use consistent height (`h-9` or the default Input size). All textareas should have consistent min-height.
6. **Switch controls:** Align switches to the right of their description text, using `flex items-center justify-between` layout.
7. **Button sizing:** Action buttons (Save, Test, Delete) use `size="sm"` consistently.
8. **Empty states:** When a tab has no content (e.g., no MCP connections, no sessions), show a clean empty state with muted text centered.
9. **Error/success states:** Consistent styling for status messages.

**Specific tab improvements:**

- **Profile tab:** Name field + email display. Clean form layout with proper labels and spacing.
- **General tab:** Review and clean up any general settings. Consistent switch/toggle layouts.
- **Appearance tab:** Theme selector, color theme, font size. Use grid or clean stacked layout for options.
- **API Keys tab:** API key input with test button. Clean form with helper text explaining what the key is for.
- **MCP tab:** Connection list with add/edit/delete. Cards or list items with consistent spacing. Clean empty state.
- **Instructions tab:** Custom instructions textarea. Clean layout with character/token count if present.
- **Sessions tab:** Session list with revoke actions. Clean table or list layout.
- **Advanced tab:** Any advanced settings. Clean layout.

**Important constraints:**
- Do NOT change any functionality -- only visual styling
- Do NOT consolidate or remove tabs
- Do NOT change the tab order
- Use semantic color classes only (no hardcoded colors)
- Ensure dark mode compatibility
- Test that no content is cut off or unreachable
