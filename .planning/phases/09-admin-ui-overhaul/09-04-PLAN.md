<task type="auto">
  <name>Task 2: Update session lastUsedAt on each authenticated request</name>
  <files>lib/auth-middleware.ts</files>
  <action>
In the `requireAuth` function (or whichever function validates the session token and returns the user), add a non-blocking update to set `lastUsedAt = new Date()` on the session record after successful validation.

The update should be fire-and-forget (do NOT await it) to avoid adding latency to every request. Use:

```typescript
// Fire-and-forget: update lastUsedAt without blocking the response
prisma.session.update({
  where: { id: session.id },
  data: { lastUsedAt: new Date() },
}).catch(() => {/* ignore update errors */});
```

Place this after the session is validated and before the return statement. The Session model already has `lastUsedAt DateTime? @map("last_used_at")` in the schema.

This fixes the "Active Never" issue in the Settings modal Sessions tab, where `getRelativeTime(session.lastUsedAt)` returns "Never" because `lastUsedAt` was null (never populated).

Do NOT throttle this update -- the overhead of a simple timestamp update on an indexed row is negligible, and accuracy matters more for session management UX.
