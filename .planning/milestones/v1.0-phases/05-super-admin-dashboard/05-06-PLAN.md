**2. Analytics service (lib/services/platform-analytics-service.ts):**

All queries use raw `prisma` (cross-org, platform-level). Use `prisma.$queryRaw` for date-grouped aggregations (established pattern from Phase 4 usage-service.ts).

Functions grouped by analytics section:

**getKpiSummary():** Returns:
- `totalOrgs`: Count of orgs where deletedAt is null, broken down by status (active, suspended)
- `totalUsers`: Count of distinct users across all org members (active, suspended)
- `totalConversations`: Count of conversations
- `totalMessages`: Count of messages
- `totalTokens`: Sum of (inputTokens + outputTokens + thinkingTokens) from UsageRecord

**getUsageTrends(startDate, endDate):** (SANA-05)
- Raw SQL: GROUP BY DATE(created_at), sum tokens. Return array of `{ date, inputTokens, outputTokens, thinkingTokens }`.
- Pattern from Phase 4: `SELECT DATE(created_at) as date, SUM(input_tokens) ...`

**getTokensByOrgModel(startDate, endDate):** (SANA-04)
- Raw SQL: GROUP BY organization_id, model, DATE(created_at). Return nested structure for stacked area chart.

**getTopOrgsByUsage(startDate, endDate, limit=10):** (SANA-06)
- GROUP BY organization_id, SUM tokens, ORDER BY total DESC, LIMIT 10. Join with org name.

**getErrorRates(startDate, endDate):** (SANA-07)
- Count UsageRecord entries where metadata contains errorType (using Prisma JSON filtering or raw SQL). Group by error type. Return `{ type, count }[]`.
- If no error tracking exists yet, return empty array with a note that error tracking will be populated as errors occur.

**getPeakUsageHours(startDate, endDate):** (SANA-08)
- Raw SQL: `SELECT EXTRACT(HOUR FROM created_at) as hour, EXTRACT(DOW FROM created_at) as day, COUNT(*) as count FROM usage_records WHERE ... GROUP BY hour, day`
- Return `{ hour: number, day: number, count: number }[]` for heatmap

**getApiKeyConsumption(startDate, endDate):** (SANA-09)
- Aggregate UsageRecord by org, join with PlatformApiKeyAssignment to associate keys. Since exact key per request isn't tracked, derive from assignment: for each org's usage, attribute to the key(s) assigned to that org.

**getMcpUsageTrends(startDate, endDate):** (SANA-10)
- Count messages with role='tool' grouped by date. Also count unique tool names from message metadata if available.

**getRegistrationTrends(startDate, endDate):** (SANA-11)
- Orgs: GROUP BY DATE(created_at) from Organization
- Users: GROUP BY DATE(joined_at) from OrgMember

**getFeatureAdoption(startDate, endDate):** (SANA-12)
- Count distinct orgs using each feature in the time period:
  - Web search: orgs with UsageRecord where metadata indicates web search used (or conversations with web search flag)
  - File uploads: orgs with messages containing file attachments
  - MCP tools: orgs with messages of role='tool'
  - Artifacts: orgs with Artifact records
  - Thinking: orgs with UsageRecord where thinkingTokens > 0
- Return `{ feature, orgCount, percentage }[]`

**3. API route (app/api/super-admin/analytics/route.ts):**

GET: requireSuperAdmin -> Parse query params (startDate, endDate, section?) -> Call analytics service functions -> Return combined JSON.

Query params:
- `startDate` and `endDate` (ISO strings, required)
- `section` (optional: "kpi" | "trends" | "topOrgs" | "errors" | "peakHours" | "apiKeys" | "mcp" | "registrations" | "adoption" | "all")

When section is "all" or omitted, call all functions and return combined object. When specific section requested, return only that data (for lazy loading individual sections).

This allows the frontend to load KPI cards first (fast query) and then load charts in parallel.
