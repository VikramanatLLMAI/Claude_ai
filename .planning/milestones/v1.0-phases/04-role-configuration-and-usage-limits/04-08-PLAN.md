<objective>
Fix BLOCKER org login page missing slug (sessions created with null organizationId) and MAJOR missing auto-redirect for force-password-change.

Purpose: The org login page POSTs to /api/auth/login without the org slug. This causes sessions to be created without an organizationId, which breaks: (1) forcePasswordChange detection at login, (2) session listing by org, and (3) force-logout for org users. Additionally, the chat page has no handler for 403 FORCE_PASSWORD_CHANGE responses from the API.

Output: Org login correctly passes slug to login route, sessions carry organizationId, force-password-change detection works at login, and chat page redirects to force-password-change on 403.
</objective>

<task id="2" title="Add 403 FORCE_PASSWORD_CHANGE interceptor in chat app">
<description>
Handle 403 FORCE_PASSWORD_CHANGE responses in the chat page so users who navigate directly to chat are redirected.

**Step 1: Add global fetch interceptor for FORCE_PASSWORD_CHANGE**
File: `components/full-chat-app.tsx`
- Find where API calls are made (useChat hook, conversation loading, model loading, etc.)
- The most critical interception points are:
  a. The initial data loading (models, conversations) — these happen on mount and will return 403 first
  b. The useChat `onError` or `onResponse` callback
- Add a helper function near the top of the component:
  ```typescript
  const handleForcePasswordChange = useCallback((response: Response) => {
    if (response.status === 403) {
      response.clone().json().then((data) => {
        if (data.code === 'FORCE_PASSWORD_CHANGE' && data.redirectTo) {
          window.location.href = data.redirectTo;
        }
      }).catch(() => {});
    }
  }, []);
  ```
- Find the main data fetching functions (look for `fetch(` calls that load models, conversations, etc.)
- After each fetch response check, add the FORCE_PASSWORD_CHANGE check. For example:
  ```typescript
  const res = await fetch(`/api/org/${orgSlug}/...`, { headers });

    const data = await res.json();
    if (data.code === 'FORCE_PASSWORD_CHANGE' && data.redirectTo) {
      window.location.href = data.redirectTo;
      return;
    }
  }
  ```
- Focus on the FIRST fetch calls that happen on page load — typically the models fetch or user info fetch
- If there's a centralized fetch wrapper, hook in there. Otherwise, add the check to the 1-2 most prominent fetch calls that happen on mount.
