# Plan 04-13: Deprecate Model Confirmation Dialog

## Objective

Add a confirmation dialog before the model deprecation API call fires, using the same Dialog pattern already present for the Delete action in `model-registry-table.tsx`.

## Context

Playwright UAT found that clicking the orange circle-slash (Ban) icon on `/admin/models` immediately deprecated the model with no confirmation. The delete action already has a proper Dialog confirmation in `model-registry-table.tsx` (lines 319-343). The deprecate action bypasses this — clicking the button calls `onDeprecate(model)` directly, which triggers the PATCH API call with no user prompt.

The fix is entirely within `model-registry-table.tsx`. The page-level `handleDeprecate` function in `app/admin/models/page.tsx` is correct as-is and does not need to change.

## Key Observation

The existing delete confirmation pattern in `model-registry-table.tsx`:
1. State: `deleteTarget` (line 104)
2. Button `onClick`: `setDeleteTarget(model)` (line 300)
3. Confirm handler: calls `onDelete(deleteTarget)` then clears state (lines 125-130)
4. Dialog JSX: `open={!!deleteTarget}`, Cancel clears state, Confirm calls handler (lines 319-343)

Apply the exact same pattern for deprecate.

## Implementation Tasks

### Task 1: Add Deprecate Confirmation Dialog to ModelRegistryTable (BUG-4)

**File**: `components/admin/model-registry-table.tsx`

**Change**: Add `deprecateTarget` state, wire the Ban button to set it instead of calling `onDeprecate` directly, add a confirm handler, and render a Dialog for confirmation.

**Details**:

**Step 1 — Add state** (after line 104, alongside `deleteTarget` state):

```typescript
const [deprecateTarget, setDeprecateTarget] = React.useState<ModelData | null>(null)
```

**Step 2 — Add confirm handler** (after the existing `handleDeleteConfirm` function, lines 125-130):

```typescript
const handleDeprecateConfirm = () => {
  if (deprecateTarget) {
    onDeprecate(deprecateTarget)
    setDeprecateTarget(null)
  }
}
```

**Step 3 — Update Ban button onClick** (line 291, currently `onClick={() => onDeprecate(model)}`):

Change from:
```typescript
onClick={() => onDeprecate(model)}
```

To:
```typescript
onClick={() => setDeprecateTarget(model)}
```

**Step 4 — Add deprecate confirmation Dialog** (after the existing Delete Dialog, after line 343, before the closing `</>`):

```typescript
{/* Deprecate confirmation dialog */}
<Dialog
  open={!!deprecateTarget}
  onOpenChange={(open) => !open && setDeprecateTarget(null)}
>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>Deprecate Model</DialogTitle>
      <DialogDescription>
        Are you sure you want to deprecate{" "}
        <strong>{deprecateTarget?.displayName}</strong>? The model will
        be marked as deprecated and hidden from new role assignments.
        Existing roles that reference this model will continue to work.
      </DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <Button variant="outline" onClick={() => setDeprecateTarget(null)}>
        Cancel
      </Button>
      <Button
        variant="default"
        className="bg-amber-600 hover:bg-amber-700 text-white"
        onClick={handleDeprecateConfirm}
      >
        Deprecate
      </Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

No imports need to be added — `Dialog`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogFooter`, and `Button` are already imported at the top of this file (lines 17-23).

**What NOT to change**: `app/admin/models/page.tsx` — the `handleDeprecate` function there is correct. The confirmation guard moves into the table component where the button lives, not the page.
