  3. Role create/edit modal with 4 tabs (General, Models & Tools, Limits, Permissions)
  4. Custom role CRUD (create, edit, delete with guards)
  5. Usage limit enforcement in chat route (429 at 100%)
  6. Chat UI usage banners (amber at 80%, red + disabled input at 100%)
  7. Usage monitoring dashboard with summary cards, trend chart, per-user table
  8. Password policy management security page
  9. Force password reset (individual + bulk)
  10. Forced password change page with login redirect
  11. User profile management (name, avatar) in settings modal
  12. Session management (view, revoke) in settings modal
  13. SAFE-11: Conversation read-only enforcement for Org Admin
  14. OROL-07: Custom instructions 200 token budget enforcement for custom roles
  15. ODEF-02: Default role deletion clears org default automatically
  </what-built>
  <how-to-verify>
  Start the dev server: `npm run dev`

  **A. Admin Sidebar (visual)**
  1. Log in as Org Admin, navigate to admin console
  2. Verify sidebar shows 4 groups: Configuration (Roles, Instructions, MCP Servers), Monitoring (Usage), Security (Password Policy), People (Members, Invitations)
  3. Verify existing pages (Instructions, MCP Servers) still work via sidebar links

  **B. Role Management**
  4. Navigate to Roles page -- verify read-only cards with member counts
  5. Click "Create Role" -- verify 4-tab modal opens
  6. Create a custom role with name, description, models, limits, permissions -- verify it appears in the list
  7. Click "Edit" on the new role -- verify modal pre-fills with current settings
  8. Try to delete the custom role -- verify it succeeds (if no members assigned)
  9. Assign a user to the custom role, try to delete -- verify deletion is blocked with error
  10. Try to delete a system role -- verify no delete button exists
  11. Edit a system role (rename, change models) -- verify it saves

  **C. Usage Limits**
  12. Set a low daily request limit (e.g., 3) on a role via the edit modal Limits tab
  13. Log in as a user with that role, send 2 messages -- verify amber warning banner appears at 80%
  14. Send 1 more message -- verify red banner appears and chat input is disabled
  15. Try sending a message via API -- verify 429 response
  16. Navigate to Usage dashboard as Org Admin -- verify the user shows with "Blocked" status

  **D. Password Policy**
  17. Navigate to Security page as Org Admin
  18. Set minimum length to 12, enable uppercase requirement -- save
  19. Click "Force Reset All Users" -- verify confirmation dialog
  20. Confirm force reset -- verify success toast with user count
  21. Log out and log in as a regular user -- verify redirect to force password change page
  22. Enter a weak password (e.g., "short") -- verify validation errors
  23. Enter a compliant password -- verify success and redirect to chat

  **E. Profile & Sessions**
  24. Open settings modal, verify Profile tab is first
  25. Change display name -- verify it saves
  26. Upload an avatar image -- verify preview, auto-crop, and save
  27. Verify email shows as read-only with lock icon
  28. Verify role shows as read-only badge
  29. Switch to Sessions tab -- verify current session is marked
  30. If multiple sessions exist, revoke one -- verify it disappears from list

  **F. SAFE-11: Conversation Read-Only Enforcement**
  31. As Org Admin, attempt to PATCH another user's conversation via API (e.g., `curl -X PATCH /api/conversations/[other-user-conv-id]`) -- verify 403 response
  32. As Org Admin, attempt to DELETE another user's conversation via API -- verify 403 response
  33. As the conversation owner, verify PATCH and DELETE still work on own conversations

  **G. OROL-07: Custom Instructions Token Budget**
  34. Assign a user to a custom role that has customInstructionsEnabled=true
  35. Log in as that user, open settings modal, navigate to Custom Instructions
  36. Verify the live token counter shows and is capped at 200 tokens (InstructionEditor maxTokens prop from the role)

  **H. ODEF-02: Default Role Deletion Cascade**
  37. As Org Admin, set a custom role as the org's default role
  38. Remove all users from that custom role, then delete it
  39. Verify the org's defaultRoleId is now null (next invitation should require explicit role selection)

  **I. Force-Logout UI Surface**
  40. Navigate to Usage dashboard as Org Admin
  41. In the per-user usage table, click the actions menu (three-dot/kebab) for a regular user
  42. Click "Force Logout" -- verify confirmation dialog appears
  43. Confirm force logout -- verify success toast showing number of sessions revoked
