  <files>components/chat/usage-banner.tsx</files>
  <action>
Find lines 128-129 in the component, which currently read:

```typescript
const primaryStatus = status.requestStatus ?? status.tokenStatus
const isRequestBased = !!status.requestStatus
```

Replace those two lines with:

```typescript
const reqPct = status.requestStatus?.percentage ?? -1
const tokPct = status.tokenStatus?.percentage ?? -1
const primaryStatus = reqPct >= tokPct ? status.requestStatus : status.tokenStatus
const isRequestBased = primaryStatus === status.requestStatus
```

No other lines in the file change. The `label`, `currentFormatted`, `limitFormatted`, and `percentage` variables on lines 130-133 already derive from `primaryStatus` and `isRequestBased` — they will automatically reflect the correct metric once the two lines above are replaced.

Rationale: The old code always preferred request metrics because `??` picks the first non-null value. The new code computes the percentage for each metric (defaulting to -1 when null so null metrics always lose) and selects whichever is higher. When both percentages are equal, requests win (>= favours requests), which is a safe tie-break. The updated `isRequestBased` derives from identity comparison against the chosen `primaryStatus`, correctly labelling the display as "requests" or "tokens".

Do NOT change any other logic in the file — the warning banner path (non-blocked case) at lines 178-179 also computes max percentage but is used for the progress bar fill, not display text, so it is unaffected.
