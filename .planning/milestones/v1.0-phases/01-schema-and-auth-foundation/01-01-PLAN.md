**Step 1: Create lib/tenant.ts — tenant-scoped Prisma Client Extension factory (SCHEMA-03)**

Create a new file `lib/tenant.ts` that exports a `tenantPrisma(orgId)` function. This is the SINGLE enforcement point for data isolation.

Implementation details:
- Import `prisma` from `./db`
- Define `TENANT_SCOPED_MODELS` as a Set containing model names that have organizationId: `['Conversation', 'Message', 'Artifact', 'McpConnection', 'OrgMember', 'Role', 'Invitation', 'AuditLog', 'UsageRecord', 'OrgSettings', 'OrgThemeAssignment', 'PasswordPolicy', 'PlatformApiKey']`
- Define `READ_OPS` Set: `['findUnique', 'findUniqueOrThrow', 'findFirst', 'findFirstOrThrow', 'findMany', 'count', 'aggregate', 'groupBy']`
- Define `WRITE_OPS` Set: `['create', 'createMany', 'update', 'updateMany', 'delete', 'deleteMany', 'upsert']`
- Use `prisma.$extends()` with `query.$allModels.$allOperations` interceptor
- For tenant-scoped models:
  - READ ops: inject `organizationId: orgId` into `args.where`
  - CREATE ops: inject `organizationId: orgId` into `args.data`
  - CREATE_MANY ops: inject into each item in `args.data` array
  - UPDATE/DELETE ops: inject into `args.where`
  - UPSERT ops: inject into both `args.where` and `args.create`
- For non-tenant-scoped models (User, Session, PasswordResetToken): pass through unmodified
- Export type alias for the extended client: `export type TenantPrismaClient = ReturnType<typeof tenantPrisma>`

Follow the exact code pattern from 01-RESEARCH.md "Pattern 1: Tenant-Scoped Prisma Client Extension".

IMPORTANT: Add a JSDoc comment at the top explaining: "Tenant-scoped Prisma client. Use `tenantPrisma(orgId)` for ALL org-scoped data access. Use the raw `prisma` client from `./db` ONLY for platform-level queries (User, Session, Super Admin operations)."

**Known limitation to document in code comments:** Prisma Client Extensions `$allModels.$allOperations` do NOT intercept nested operations (include, select with nested creates). Nested reads via `include` are safe because FK relationships enforce org scope. For nested writes, always use separate top-level operations.
