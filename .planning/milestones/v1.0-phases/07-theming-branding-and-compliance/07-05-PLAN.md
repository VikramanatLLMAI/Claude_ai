```typescript
// Start impersonation: create a session as the target user
async function startImpersonation(
  superAdminId: string,
  targetUserId: string,
  durationMinutes: 15 | 30 | 60,
  reason: string,
  ipAddress: string
): Promise<{ token: string, orgSlug: string }>
// 1. Verify superAdminId is a Super Admin
// 2. Get target user's org membership (find their primary org)
// 3. Create a new Session for the target user with:
//    - impersonatorId = superAdminId
//    - impersonationReason = reason
//    - impersonationExpiresAt = now + durationMinutes
//    - expiresAt = now + durationMinutes (session itself also expires)
//    - organizationId = target user's org
// 4. Audit log (platform): "impersonation_started" with { targetUserId, reason, duration, targetOrg }
// 5. Return the session token + target user's org slug (for redirect)

// End impersonation: invalidate the impersonation session
async function endImpersonation(sessionToken: string, superAdminId: string, ipAddress: string): Promise<void>
// 1. Find session by token, verify impersonatorId matches
// 2. Delete the impersonation session
// 3. Audit log (platform): "impersonation_ended" with { targetUserId, duration }

// Get impersonation status
async function getImpersonationStatus(sessionToken: string): Promise<{
  isImpersonating: boolean,
  impersonatorName?: string,
  targetUserName?: string,
  reason?: string,
  expiresAt?: Date
} | null>
```

**User search API** (app/api/super-admin/users/route.ts):

- GET: Search users across all orgs. Query params: `search` (name or email), `page`, `pageSize`.
- Returns: `{ users: Array<{ id, name, email, orgName, orgSlug, roleName, status }>, total }`
- Uses requireSuperAdmin.
- Joins User -> OrgMember -> Organization -> Role for full context.

**Start impersonation API** (app/api/super-admin/users/[id]/impersonate/route.ts):

- POST: Body `{ duration: 15 | 30 | 60, reason: string }`. Both fields required (Zod validation).
- Calls `impersonationService.startImpersonation()`.
- Returns `{ token, orgSlug }` — the frontend stores this as the active session and redirects to the org.

**Impersonation management API** (app/api/super-admin/impersonation/route.ts):

- GET: Check current impersonation status. Returns impersonation details or `{ isImpersonating: false }`.
- DELETE: End impersonation. Calls `endImpersonation()`. Returns success.
- Both use the current session token from Authorization header.

**Auth middleware changes** (lib/auth-middleware.ts):

In `validateSession()` or wherever sessions are validated:
1. Check if `session.impersonationExpiresAt` exists and is past → auto-expire: delete session, return null (auto-expiry).
2. When session has `impersonatorId`, ALL audit logs during this session should include `impersonatorId` in metadata. Modify the auth context to carry `impersonatorId` so downstream audit log calls can include it.
3. Add `impersonatorId` to the auth context type returned by requireOrgAuth/requireAuth.

IMPORTANT: The impersonation session is a real session as the target user. The auth middleware treats it as the target user for all authorization checks. The impersonatorId is metadata for audit trail only.
