# Phase 10.1: Migrate Recharts to shadcn/ui Charts - Research

**Researched:** 2026-03-07
**Domain:** shadcn/ui Chart components (Recharts wrapper), CSS variable theming
**Confidence:** HIGH

## Summary

This phase replaces direct Recharts usage in 18 chart components across two files (Super Admin analytics and Org Admin analytics) with shadcn/ui Chart wrapper components. shadcn/ui Charts are a thin composition layer over Recharts that adds: `ChartContainer` (replaces `ResponsiveContainer` and injects CSS variables), `ChartTooltip`/`ChartTooltipContent` (themed tooltips), and `ChartLegend`/`ChartLegendContent` (themed legends). The underlying Recharts components (AreaChart, BarChart, PieChart, Bar, Area, Pie, XAxis, YAxis, CartesianGrid, Cell) remain identical -- the migration changes how they are wrapped and how colors/tooltips/legends are configured.

The project already has `--chart-1` through `--chart-5` CSS variables defined in `globals.css` for all 5 themes (Claude, Vercel, Solar Dusk, Twitter, Violet Bloom) in both light and dark modes, with corresponding `--color-chart-*` mappings in the `@theme` section. This means the color infrastructure is already in place. The main work is: (1) creating the `chart.tsx` wrapper component, (2) rewriting each chart to use `ChartContainer` + `ChartConfig` + `ChartTooltip` + `ChartLegend`, (3) extracting shared utilities to `chart-utils.tsx`, and (4) removing the direct `recharts` dependency.

**Primary recommendation:** Manually create `components/ui/chart.tsx` (the project lacks `components.json` for the shadcn CLI). Use the well-documented shadcn/ui chart component pattern. Each chart migration is mechanical: replace `ResponsiveContainer` with `ChartContainer`, replace `Tooltip` with `ChartTooltip`, replace `Legend` with `ChartLegend`, define a `ChartConfig` object, and reference colors via `var(--color-{key})`.

### Pattern 1: ChartConfig + ChartContainer
**What:** Each chart defines a `ChartConfig` object that maps data keys to labels and colors, then wraps the Recharts chart in `ChartContainer` instead of `ResponsiveContainer`.
**When to use:** Every chart component.
**Example:**
```typescript
// Source: shadcn/ui chart documentation
import { ChartContainer, ChartTooltip, ChartTooltipContent, ChartLegend, ChartLegendContent } from "@/components/ui/chart"
import { type ChartConfig } from "@/components/ui/chart"
import { AreaChart, Area, CartesianGrid, XAxis, YAxis } from "recharts"

const chartConfig = {
  inputTokens: {
    label: "Input",
    color: "var(--chart-1)",
  },
  outputTokens: {
    label: "Output",
    color: "var(--chart-2)",
  },
  thinkingTokens: {
    label: "Thinking",
    color: "var(--chart-3)",
  },
} satisfies ChartConfig

export function UsageTrendChart({ data }: { data: UsageTrendPoint[] }) {
  return (
    <Card>
      <CardHeader>
        <CardTitle className="text-base">Usage Trends</CardTitle>
      </CardHeader>
      <CardContent>
        {data.length === 0 ? (
          <EmptyState message="No usage data in this period" />
        ) : (
          <ChartContainer config={chartConfig} className="min-h-[300px] w-full">
            <AreaChart data={data} accessibilityLayer>
              <CartesianGrid vertical={false} />
              <XAxis dataKey="date" tickLine={false} axisLine={false} tickFormatter={formatDate} />
              <YAxis tickLine={false} axisLine={false} tickFormatter={formatTokens} />
              <ChartTooltip content={<ChartTooltipContent />} />
              <ChartLegend content={<ChartLegendContent />} />
              <Area type="monotone" dataKey="inputTokens" stackId="1" fill="var(--color-inputTokens)" fillOpacity={0.2} stroke="var(--color-inputTokens)" strokeWidth={2} />
              <Area type="monotone" dataKey="outputTokens" stackId="1" fill="var(--color-outputTokens)" fillOpacity={0.2} stroke="var(--color-outputTokens)" strokeWidth={2} />
              <Area type="monotone" dataKey="thinkingTokens" stackId="1" fill="var(--color-thinkingTokens)" fillOpacity={0.2} stroke="var(--color-thinkingTokens)" strokeWidth={2} />
            </AreaChart>
          </ChartContainer>
        )}
      </CardContent>
    </Card>
  )
}
```

### Pattern 3: Pie/Donut Charts with ChartConfig
**What:** Pie chart data items include a `fill` property that references the CSS variable injected by ChartContainer.
**When to use:** ErrorRateChart, InvitationStatusChart (donut charts).
**Example:**
```typescript
// Data items must include fill property for pie charts
const chartData = data.map(item => ({
  ...item,
  fill: `var(--color-${item.type})`,  // references ChartConfig key
}))

<Pie data={chartData} dataKey="count" nameKey="type" innerRadius={60} outerRadius={100} />
```

### Pattern 4: ExportButton with Card Header
**What:** The ExportButton stays in the CardHeader alongside CardTitle. No structural change needed since ChartContainer replaces ResponsiveContainer inside CardContent.
**When to use:** All org admin charts that have onExport prop.

### Anti-Patterns to Avoid
- **Hardcoded hex colors in fill/stroke:** Use `var(--color-{configKey})` or `var(--chart-N)` instead. Exception: semantic colors in ChartConfig definitions.
- **Using ResponsiveContainer:** Replace with `ChartContainer` which handles responsive sizing and CSS variable injection.
- **Custom renderCustomLabel on Pie charts:** Use shadcn default label behavior instead.
- **Gradient fills on area charts:** User explicitly chose solid fills with low opacity (shadcn default).
- **Using Recharts Tooltip/Legend directly:** Use ChartTooltip/ChartLegend wrappers for consistent theming.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Chart tooltips | Custom Recharts Tooltip formatter | `ChartTooltipContent` from chart.tsx | Handles theme-aware styling, indicator dots, label formatting |
| Chart legends | Recharts Legend with custom formatter | `ChartLegendContent` from chart.tsx | Consistent with shadcn design system |
| Responsive chart sizing | ResponsiveContainer | `ChartContainer` | Also injects CSS variables from ChartConfig |
| Color variable injection | Manual CSS-in-JS | `ChartContainer` + `ChartConfig` | Automatically creates `--color-{key}` CSS variables |

**Key insight:** The shadcn/ui chart wrapper is deliberately thin. The Recharts components underneath remain identical. The value comes from consistent tooltip/legend styling and CSS variable-based color management.

## Common Pitfalls

### Pitfall 1: Recharts v3 TypeScript Compatibility with chart.tsx
**What goes wrong:** The official shadcn/ui chart.tsx was written for Recharts v2. Recharts v3 removed internal props (`payload`, `label`, `item`, `index`) from tooltip/legend component types.
**Why it happens:** shadcn/ui has not yet released an official Recharts v3 update (GitHub issue #7669 still open as of Feb 2026).
**How to avoid:** Use the community-verified Recharts v3-compatible chart.tsx that properly types tooltip and legend props. The project already uses `as any` casts for Recharts v3 tooltip formatters, so this is familiar territory.
**Warning signs:** TypeScript errors on ChartTooltipContent or ChartLegendContent props.

### Pitfall 2: Pie Chart Fill References
**What goes wrong:** Pie chart slices don't pick up colors from ChartConfig.
**Why it happens:** Unlike Bar/Area charts where you set `fill="var(--color-{key})"` directly on the component, Pie charts need the `fill` property on each data item.
**How to avoid:** Map data to include `fill: "var(--color-{configKey})"` before passing to Pie. Each data item's key must match a key in ChartConfig.
**Warning signs:** All pie slices render the same default color.

### Pitfall 3: ChartContainer Height
**What goes wrong:** Chart renders with zero height.
**Why it happens:** ChartContainer requires explicit minimum height via className (e.g., `min-h-[300px]`), unlike ResponsiveContainer which takes a `height` prop.
**How to avoid:** Always set `className="min-h-[{height}px] w-full"` on ChartContainer. For dynamic heights (e.g., horizontal bar charts with variable row counts), compute and pass the value.
**Warning signs:** Chart area collapses or is invisible.

### Pitfall 4: Gradient IDs Conflicting
**What goes wrong:** When multiple charts on the same page use the same gradient ID (e.g., "inputGrad"), they reference each other's gradients.
**Why it happens:** SVG `<defs>` IDs are document-global.
**How to avoid:** Since the user decided to use solid fills with low opacity (not gradients), this is avoided entirely. No gradient defs needed.
**Warning signs:** Charts show wrong gradient colors.

### Pitfall 5: Missing color- Prefix in Fill/Stroke
**What goes wrong:** Chart series renders with no color.
**Why it happens:** ChartContainer injects CSS variables as `--color-{configKey}`, not `--chart-{N}`. You must reference them as `var(--color-inputTokens)`, not `var(--chart-1)`.
**How to avoid:** Always use `var(--color-{configKey})` where `{configKey}` matches a key in your ChartConfig object.
**Warning signs:** Series renders in black or invisible.

The component needs to be created at `components/ui/chart.tsx`. It exports:
- `ChartContainer` -- wraps Recharts chart, injects CSS vars from config, handles responsive sizing

## Open Questions

1. **ChartTooltipContent formatter for custom value formatting**
   - What we know: shadcn/ui ChartTooltipContent has a `formatter` prop but it may overwrite the entire styled content. A community-suggested `valueFormatter` is not officially supported.
   - What's unclear: Whether the built-in formatter can handle `formatTokens()` output without losing styling.
   - Recommendation: Test the `formatter` prop during implementation. If it breaks styling, use the `labelFormatter` on ChartTooltip (which passes through to Recharts) or create a custom tooltip content wrapper.

2. **Dynamic series in TokensByOrgChart**
   - What we know: TokensByOrgChart has dynamically generated org names as Area dataKeys. ChartConfig must be built dynamically.
   - What's unclear: Whether ChartContainer handles dynamically constructed configs well.
   - Recommendation: Build ChartConfig dynamically from the org names array, assigning `var(--chart-N)` colors in rotation. This should work since ChartContainer just reads the config object.

3. **chart.tsx Recharts v3 compatibility**
   - What we know: The official shadcn/ui chart.tsx targets Recharts v2. Community fix exists for v3 (GitHub issue #7669).
   - What's unclear: Exact changes needed for the v3-compatible version.
   - Recommendation: Start with the official chart.tsx source, apply v3 type fixes if TypeScript errors occur. The project already uses `as any` casts for v3 compatibility, so worst case, the same pattern works in chart.tsx.
