# Phase 10.1: Migrate Recharts to shadcn/ui Charts - Context

**Gathered:** 2026-03-07
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace all direct Recharts usage in admin analytics dashboards with shadcn/ui Chart components. The result should look and feel like the official shadcn/ui charts dashboard — fully theme-aware, type-safe, and consistent with the existing shadcn component library already used throughout the app. Remove the direct recharts dependency when complete.

</domain>

<decisions>
## Implementation Decisions

### Color & Theming Strategy
- Use shadcn/ui's ChartConfig with CSS variables (--chart-1 through --chart-5) for general chart series
- Colors auto-adapt to light/dark mode — no more hardcoded hex values
- Semantic colors (error types: red=rate_limit, amber=context_length; invitation status: green=accepted, red=revoked) stay as fixed meaningful colors — not theme-variable-driven
- Global chart palette defined in globals.css for light/dark modes — NOT per-org-theme chart colors

### Code Deduplication
- Create `components/admin/chart-utils.tsx` for shared utilities: EmptyState component, formatters (formatTokens, formatDate, formatMs), color constants, label renderers
- Keep two separate chart files: `analytics-charts.tsx` (Super Admin) and `org-analytics-charts.tsx` (Org Admin)
- ChartConfig objects defined per-chart inline (not centralized) — configs are small and chart-specific
- All chart files stay in `components/admin/` directory (charts are admin-only)

### Migration Scope
- Migrate all 18 Recharts-based chart components to shadcn/ui Charts in one pass
- Keep 2 CSS grid heatmaps as-is (they don't use Recharts)
- Keep 2 HTML table components as-is
- Remove `recharts` from package.json direct dependencies after migration (shadcn/ui Charts brings its own recharts dependency)
- Remove recharts from Sandpack dependency list (`lib/sandpack-deps.ts`) — chart generation is not a common artifact use case
- shadcn/ui components cannot work in Sandpack (requires Tailwind + CSS variables + Radix)

### Visual Changes
- Adopt shadcn/ui Chart's built-in tooltip, legend, and grid styling (shadcn defaults)
- Use solid fills with low opacity for area charts (shadcn default) — NOT gradient fills
- Use shadcn default label positioning for donut/pie charts — remove custom `renderCustomLabel` function
- Target: charts should look like the official shadcn/ui charts dashboard
- Production-grade quality — this is a production SaaS application

### Claude's Discretion
- Exact ChartConfig color assignments per chart
- Whether to use ChartStyle component for gradient IDs or inline defs
- Tooltip content formatting details within shadcn's ChartTooltipContent
- How to handle the ExportButton integration with new chart wrapper structure

</decisions>

<specifics>
## Specific Ideas

- "I need it to look like the shadcn dashboard exactly" — target the official shadcn/ui charts demo aesthetic
- "We already use shadcn components for the dashboard, so using the same chart components will look good" — consistency with existing UI is a key motivation
- Charts should feel native to the shadcn design system, not like a separate charting library bolted on

- `components/ui/card.tsx`: Card, CardHeader, CardContent, CardTitle — already used by all chart components

- shadcn/ui components use CVA (class-variance-authority) + cn() utility
