<task type="auto">
  <name>Task 2: Wire Zod validation into unvalidated mutation routes</name>
  <files>Multiple route.ts files across app/api/org/[slug]/admin/ and app/api/super-admin/</files>
  <action>
For each mutation route that currently parses `req.json()` without validation, add Zod validation using the existing pattern:

```typescript
import { validate, formatValidationErrors, SomeSchema } from '@/lib/validation';

// In the route handler, after auth check:
const body = await req.json();
const { success, data, errors } = validate(SomeSchema, body);
if (!success) {
  return NextResponse.json(
    { error: 'Validation failed', details: errors!.map(e => ({ field: e.path.join('.'), message: e.message })) },
    { status: 400 }
  );
}
// Use data (type-safe) instead of body
```

Apply to all routes identified in the audit. Key groups:

**Org Admin routes** (`app/api/org/[slug]/admin/`):
- `roles/route.ts` -- POST (create role), roles/[id]/route.ts PATCH/DELETE
- `users/[id]/route.ts` -- PATCH (user actions like suspend, change-role)
- `themes/route.ts` -- POST (assign theme), themes/[name]/route.ts DELETE
- `settings/route.ts` -- PATCH (update org settings)
- `onboarding/route.ts` -- POST (accept agreement)
- `security/route.ts` -- PATCH (update password policy)
- `conversations/[id]/route.ts` -- PATCH (visibility)
- `mcp/connections/route.ts` -- POST (create org MCP connection)
- `mcp/connections/[id]/route.ts` -- PATCH/DELETE

**Super Admin routes** (`app/api/super-admin/`):
- `organizations/[id]/route.ts` -- PATCH (org actions)
- `role-templates/route.ts` -- POST, role-templates/[id]/route.ts PATCH/DELETE

**General routes:**
- `artifacts/route.ts` -- POST (create artifact)
- `artifacts/[id]/route.ts` -- PATCH (update artifact)
- `user/settings/route.ts` -- PATCH (update user settings)
- `user/anthropic/route.ts` -- POST (set Anthropic key)

For each route:
1. Read the route file to understand the expected body shape
2. Match it to the appropriate schema from validation.ts
3. Add the validation block
4. Replace direct body property access with validated `data` object

Use the validation error format from CONTEXT.md: `{ error: 'Validation failed', details: [{ field, message }] }`

Do NOT modify routes that already import from `@/lib/validation` -- they are already validated.
