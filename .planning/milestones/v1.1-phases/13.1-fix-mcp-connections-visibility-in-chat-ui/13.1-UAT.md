## Tests

### 1. Org/Role MCP Tool Labels in Chat
expected: When an MCP tool call from an org-wide or role-scoped MCP server appears in the chat timeline, it shows an (Org) or (Role) label next to the tool name, distinguishing it from personal MCP tools which have no such label.
result: pass

### 2. Org MCP Read-Only Section in Settings
expected: Opening Settings > MCP Connections tab shows an "Organization" section above personal connections, listing org-wide MCP servers as read-only cards (no edit/delete controls). Each card shows server name, status, and tool count.
result: pass

### 3. Role MCP Read-Only Section in Settings
expected: The MCP Connections tab also shows a "Role" section listing role-scoped MCP servers as read-only cards, visually separated from org and personal sections.
result: issue
reported: "Admin MCP creation endpoint does not set source field (defaults to PERSONAL). Role MCP API queries for source='ROLE' which returns empty. Role Tools section is conditionally hidden when empty, so it never appears."
severity: blocker

### 4. Personal MCP Gating When Disabled
expected: If personalMcpEnabled is false on the user's role, the personal MCP connections section in Settings shows a disabled/informational message instead of the "Add Connection" button and connection list. Attempting to add/edit/delete personal MCPs via API returns 403.
result: issue
reported: "/api/auth/me does not return role data for org users, so personalMcpEnabled defaults to true. Add Connector dialog opens despite disabled setting. Backend correctly returns 403 but no error toast shown to user. Silent failure."
severity: blocker

### 5. Personal MCP Gating When Enabled
expected: If personalMcpEnabled is true on the user's role, the personal MCP connections section works normally -- user can add, edit, and delete personal MCP connections.
result: issue
reported: "Core flow works (add/connect/discover/delete all functional) but Edit MCP Connector dialog does not pre-populate fields -- shows placeholder text instead of saved values. Users cannot see what they're editing."
severity: major

### 6. Auto-Include Org/Role MCPs in Chat
expected: Org-wide and role-scoped MCP tools are available in chat without the user needing to manually activate them. The AI can use tools from org/role MCP servers automatically.
result: pass
