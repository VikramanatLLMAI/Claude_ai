Start the dev server and use Playwright MCP browser tools (browser_navigate, browser_snapshot, browser_click, browser_type, etc.) to execute all 12 pending browser verification tests from the v1.0 milestone audit. Use existing dev seed data (Super Admin + sample org + 2 users).

**Prerequisites:**
- Ensure database is seeded: `npm run db:seed -- --dev` (idempotent, safe to re-run)
- Start dev server: `npm run dev` (run in background)
- Wait for server to be ready on localhost:3000

**Phase 5 tests (7):**

1. **Super Admin login page renders** — Navigate to `/super-admin/login`, snapshot, verify login form renders with email/password fields and submit button

2. **Super Admin sidebar groups** — Log in as Super Admin, snapshot sidebar, verify all navigation groups display (Dashboard, Organizations, API Keys, Models, Users, Super Admins, Analytics, Audit Logs, Settings, System Prompt)

3. **Organization CRUD + dialog state** — Navigate to Organizations page, click "Create Organization" button, verify dialog opens with form fields (name, slug), submit the form, verify dialog closes, verify new org appears in table. Then test edit and delete flows.

4. **API key management: reveal/assign/delete** — Navigate to API Keys page, create a test key if none exists, click reveal button (verify key shows), click assign to org (verify assignment), click delete (verify removal)

5. **Analytics charts: time range filters** — Navigate to Analytics page, verify charts render, change time range filter, verify charts update (new data or same data with different range)

6. **Audit log export: CSV download** — Navigate to Audit Logs page, verify logs display, click export/download CSV button, verify download triggers (or verify the API endpoint returns CSV content-type)

7. **Old path /admin/* returns 404** — Navigate to `/admin/` (old path), verify 404 page renders (not the super admin dashboard)

**Phase 7 tests (5):**

8. **Theme E2E flow** — As Super Admin, assign a theme to the sample org. Then log in as Org Admin, navigate to org admin settings, select the assigned theme, verify it applies in the chat interface (CSS variables change)

9. **Login page branding** — As Org Admin, set tagline and welcome text in branding settings. Navigate to org login page, verify tagline and welcome text appear

10. **Onboarding wizard flow** — This requires a user who has NOT completed onboarding. If seed data includes such a user, navigate to chat as that user and verify wizard appears. If not, create a new invitation, register a new user, and verify the onboarding wizard renders and can be completed.

11. **Impersonation session lifecycle** — As Super Admin, navigate to Users page, click impersonate on a user, verify impersonation banner appears at top, verify browsing as impersonated user works, click "End Impersonation" button, verify banner disappears and Super Admin context restores

12. **Cron cleanup execution** — Call the cron cleanup endpoint directly: `curl -H "Authorization: Bearer {CRON_SECRET}" http://localhost:3000/api/cron/cleanup`. Verify it returns 200 and reports cleanup results.

**For each test, document:**
- Test name and ID
- Steps taken
- Expected outcome
- Actual outcome
- Status: PASS / FAIL
- If FAIL: what went wrong, fix applied (if any)

Write results to `13-BROWSER-TESTS.md`.
