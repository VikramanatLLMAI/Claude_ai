**__tests__/unit/tenant-isolation.test.ts** (TEST-03):

This test needs a different approach since tenantPrisma uses `prisma.$extends`. Instead of testing the extension mechanism directly (which requires deep Prisma internals), test the behavior by:

1. Do NOT use the mock-db setup file for this test -- it mocks `@/lib/db` which is what tenantPrisma wraps
2. Instead, mock `@/lib/db` to return an object with a `$extends` method that captures the extension callback
3. Call `tenantPrisma('org-123')` and verify the extension is applied
4. Extract the `$allOperations` callback and call it directly with test args to verify:
   - For a tenant-scoped model (e.g., 'Conversation') + 'findMany': organizationId is injected into `args.where`
   - For a tenant-scoped model + 'create': organizationId is injected into `args.data`
   - For a tenant-scoped model + 'upsert': organizationId is injected into both `args.where` and `args.create`
   - For a non-scoped model (e.g., 'User') + 'findMany': args pass through unmodified
   - For 'createMany' with array data: each item gets organizationId

The key technique: mock `prisma.$extends` to capture the config passed to it, then extract and call the `$allOperations` function directly.
